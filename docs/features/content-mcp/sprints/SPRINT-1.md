**Branch:** `content-mcp/sprint-1-read-and-price` task branches → `master` (then `master` → `kyiv`)
**Goal:** On `dev.dovira.vet` (after the user's push to `dev`), each of the three people adds the custom connector `https://dev.dovira.vet/wp-json/mcp/dovira` to their own claude.ai with their own application password and sees the `dovira/*` tools. In a chat they can ask what post types and fields the site has, list and open any service, employee, vacancy, page or blog post with its ACF values, blocks, terms and Russian copy, and — as an editor — read nothing of `conversation` / `application` / `questionary`, while an administrator reads them. Asking «зміни ціну на екстрений прийом, 550 грн» produces a preview naming the service, the row and both language copies; after consent the price is written to both, and the first such write of the session leaves a new `dovira-dev.dovira.vet-{date}-{time}.sql.gz` in `DOVIRA_MCP_DUMP_DIR` that is never overwritten; a second write in the same session adds no file. A title, status, ACF value, term or block of an existing post is changed the same way, an editor's attempt to trash a post is refused and an administrator's moves it to the trash. The dump's duration on the shared host is measured and recorded, and every rule of the write protocol is a unit test in the theme's suite.

## Fixed decisions
- DECISIONS "The content connector is the official MCP Adapter serving Dovira abilities registered by a theme feature" (2026-11-05): plugin `mcp-adapter` 0.7.x committed under `wp-content/plugins/`, feature `inc/features/content-mcp/`, server `/wp-json/mcp/dovira` listing only `dovira/*` abilities as direct tools.
- DECISIONS "Each person connects with an application password of their own WordPress user; no OAuth layer" (2026-11-05).
- DECISIONS "No UI design phase; the connector's surface is the tool catalogue and result shapes fixed in FEATURE.md" (2026-11-05): sprint steps name tools and result shapes, not screens.
- DECISIONS "A write happens only with a confirmation token issued by a preview of the same payload in the same session" (2026-11-05): one `Confirmation` service, one diff format, 15-minute transients.
- DECISIONS "A database dump is taken inside the first confirmed write of a session, into a web-closed folder, a new timestamped file every time" (2026-11-05): `Dump::ensure( $session_id )`, PHP-only, `DOVIRA_MCP_DUMP_DIR` with the `wp-content/backup-db/` fallback, 90-day retention by filter, failed dump = no write.
- DECISIONS "The tool catalogue speaks ACF field names and block names, prices have their own tools, and a price change mirrors into the Russian copy by row index" (2026-11-05): the catalogue, the post shape, `update_field()`, no default status.
- DECISIONS "The connector is verified on `dev.dovira.vet`; the adapter plugin is committed with the other plugins" (2026-11-05).
- Root `CLAUDE.md` domain invariants 2 (`service-city` never written), 3 (a row without a price shows the phone — never fabricate a price), 4 (the city from the site URL), 7 (Ukrainian is the source), 8 (validate before writing); theme `CLAUDE.md` (one registration line in `functions.php`; classes in `dovira\` namespace; secrets only as the named `wp-config.php` constants; test tooling in `tests/`).

### [x] Step 3 — The write protocol: confirmation tokens, the session dump, and the price change
- **Tasks:**
  - `Confirmation` (`dovira\ContentMcp\Confirmation`): `issue( $user_id, $session_id, array $payload, array $diff )` stores the transient `dovira_mcp_confirm_{hash}` for 15 minutes and returns the token; `verify( $token, $user_id, $session_id, $payload )` is true once — the transient is deleted on use. The session id comes from the request header `Mcp-Session-Id` the adapter passes; absent (REST, CLI) = `''`.
  - `Diff`: the one preview format of FEATURE.md → Interfaces, built from `{target:{id, lang}, field, from, to}` lines and warnings.
  - `Dump` (`dovira\ContentMcp\Dump`): `ensure( $session_id )` — if `dovira_mcp_dumped_{session}` exists, returns `"existing"`; otherwise writes `dovira-{host}-{Y-m-d}-{His}.sql.gz` (a numeric suffix when the name exists) with `$wpdb` (`SHOW TABLES`, `SHOW CREATE TABLE`, `INSERT` statements in batches, `gzopen`) into `DOVIRA_MCP_DUMP_DIR` or the fallback `WP_CONTENT_DIR . '/backup-db/'` where it first writes `.htaccess` (`Require all denied`) and an empty `index.php`; `chmod 0600`; sets the transient (24 h) and returns the file name; any failure throws, and the caller writes nothing. An empty `$session_id` means "always dump". The daily event `dovira_mcp_dump_retention` deletes dump files of this pattern older than `apply_filters( 'dovira_mcp_dump_retention_days', 90 )` days, never fewer than 1.
  - `WriteAbility` base: permission → `verify()` or `issue()` → `Dump::ensure()` → write → `{written, dump, warnings}`.
  - `PriceRows` (`dovira\ContentMcp\PriceRows`): `find( $text )` over the `prices` rows of every `service` of the install's language — case-insensitive, title and description — returning the row shape of FEATURE.md with `price` resolved: the general `price` when `is_price_general`, else the legacy column of the install's own `service-city` term (city from the site URL; a missing column = `null`, never a made-up number); `update( $service_id, $row_index, $changes )` writes `title` / `description` / `price` through `update_field()` on the repeater, into the same resolved column, never touching `is_price_general` or `cities`, and mirrors the same change into the Russian copy's row of the same index when the copies have the same number of rows — otherwise a warning and the Ukrainian copy only.
  - Abilities `dovira/find-price-rows` (readonly) and `dovira/update-price-row` (preview/write; `permission_callback`: `edit_post` of the service).
  - The server's `instructions` text: `describe-site` first; preview, show the diff, write only after consent; Ukrainian first, the Russian copy follows.
- **Tests:** `ConfirmationTest` (token bound to user, session and payload; single use; expiry), `DumpTest` with a stubbed `$wpdb` and a temp dir (file name pattern, suffix on collision, `.htaccess` + `index.php` only in the fallback, mode 0600, "existing" on a dumped session, always dumps on an empty session, a failing table throws and leaves no half file; retention deletes only matching files older than the days), `PriceRowsTest` (search, legacy column resolution per city, mirroring by index, the warning on different row counts, `is_price_general` / `cities` untouched), `update-price-row` refuses without a token and with a token of another payload. Form-to-record pipelines are not touched. The price grouping per city is a test-critical zone (root `CLAUDE.md`).
- **Verification (manual):** `DOVIRA_MCP_DUMP_DIR` defined in dev's `wp-config.php` (the spike's folder). In claude.ai: «зміни ціну на екстрений прийом, встанови 550 грн» → the agent shows a preview naming the service, the row, 450 → 550 for uk and for the ru copy, and asks; «так» → the write; `get-post` shows 550 in both copies; a new `dovira-dev.dovira.vet-…sql.gz` is in the folder (and, with the constant removed once, in `wp-content/backup-db/` whose URL answers 403). A second price change in the same chat adds no file. Changing the amount after the preview («ні, 560») produces a new preview. A row whose Russian copy has a different number of rows returns the warning. A service whose row is per-city gets its Kharkiv column changed on `dev`, and `find-price-rows` never shows a price for a column that is empty. The dump opens with `zcat … | head`.

### [ ] Step 4 — Editing an existing post, and trashing one as an administrator
- **Tasks:**
  - `PostWriter` (`dovira\ContentMcp\PostWriter`): applies a partial change set to one post — `title`, `status`, `slug`, `parent`, `menu_order`, `terms` (ids or names of `category` / `post_tag` and of `service-city` by id only — never creating a city), `acf` (nested, through `update_field()` per top-level field; a repeater value replaces the whole repeater), `blocks` for a `page` (the inverse of the reader's mapping — names → field keys — serialized with `serialize_blocks()`; a block name outside the theme's blocks is refused), `content_html` for a `post` (sanitized with `wp_kses_post`) — and computes the diff before writing. A change to a Ukrainian post does not touch its Russian copy unless the payload names the copy's id as a second target; the preview lists both.
  - Abilities `dovira/update-post` (preview/write; `permission_callback`: `edit_post`; refused for `conversation` / `application` / `questionary` — no write ability is registered for them, and `update-post` refuses the type explicitly) and `dovira/trash-post` (preview/write; `permission_callback`: `manage_options` **and** `delete_post`; `wp_trash_post()`, never `wp_delete_post()`; the preview names the post, its language and its Russian copy, which is not trashed unless named).
- **Tests:** `PostWriterTest` (partial updates; a repeater replaced whole; blocks names → keys round-trip with the reader; unknown block refused; `content_html` sanitized; the diff equals what is written; the Russian copy untouched unless targeted), `trash-post` refused for an editor and for a record type, `update-post` refused for a record type and without a token.
- **Verification (manual):** In claude.ai on `dev.dovira.vet`: «переклади статус вакансії Х на закриту» → a preview `is_open: true → false`, consent, the vacancy page shows it closed; «зміни заголовок сторінки Про нас на …» → both the Ukrainian preview and, when asked, the Russian copy's; «зміни текст у блоці hero» → the block's field changes and the page renders it; «додай рубрику Акції до новини …» → the term is attached; as an editor «видали вакансію Х» → the agent reports the refusal; as an administrator → a preview, consent, the vacancy is in the trash and restorable in wp-admin. Each change in a new chat leaves exactly one new dump.
